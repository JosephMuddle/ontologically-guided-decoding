# Script writing
Write a script in this folder which performs the following steps

# Step 1
Find at most 100 samples in the test-data.json file which contain only 1 triple and are SELECT queries. Leave out ASK queries: SPARKLE's decoder only checks that each entity and relation in an ASK query exists, so an ASK counterfactual is as reachable for SPARKLE as for our model and cannot show a difference between the two. Use a regex to do this. Write all of these samples to a json file in the counterfactuals folder called "lcquad 1 hop".
# Step 2
In each of the SPARQL queries of the lcquad 1 hop json file, replace either the subject, object, or predicate with a different subject, object or predicate. Use the tbox rules we have extracted to do this in such a way that the newly produced query preserves the range or domain (or both) of the predicate in the query. Each subject, predicate, and object MUST exist somewhere in the test data json file. Only replace subjects, predicates, or objects such that there are no corresponding triples in the DBPedia knowledge graph. You can test this out by querying against the live DBPedia endpoint which we have installed locally. This means you can write a 1 hop triple, and then query the dbpedia endpoint to determine if it has an empty answer set. If it does not have an empty answer set, try another permutation of the triple.
# Step 3
Once you have each of these SPARQL queries with empty answer sets, use the corresponding "intermediary_question" field from each of the original samples and replace the text inside the angled brackets with a standardised form of the identifiers in the new sparql queries. For example, if in the intermediary question field there is "<television shows>" and in the newly corrupted sparql query there is <http://dbpedia.org/ontology/parentOrganisation> , replace "television show" with "parent organisation". This will require regex to replace underscores or non-standard punctuation with spaces, and case normalisation. Then remove the angled brackets.
# Step 4
Save these 1 hop queries as "counterfactual 1 hops", which should have 2 fields, one being a natural language question corresponding to a counterfactual SPARQL query, and the other being the counterfactual SPARQL query itself.
# Step 5 (by hand)
Once the script has produced "counterfactual 1 hops", select the final questions by hand. This step is not part of the script, so re-running the script overwrites the hand-selected file.

First, remove every question that reads as grammatically weird. This covers number agreement errors ("Who are the partner of Dafydd Benfras?"), predicate names that do not fit the sentence ("What is the recorded in of Same Song (Digital Underground song)?"), and broken count questions ("Count the notable work in A. Peter Dewey?").

Second, remove every question that the knowledge graph answers through a different predicate. The script only guarantees that no triple exists with the query's exact predicate (or its ontology/property twin), but the knowledge graph can still answer the question through a predicate with the same meaning. For each remaining question, list every fact the local DBPedia endpoint holds about the subject, and remove the question if any of them answers it. For example, "Who is the manager of England national under-20 football team?" is answered by dbo:coach (Keith Downing), and "What is the university of Adrian A. Basora?" is answered by dbo:almaMater (Fordham University). Questions with a real-world answer that the knowledge graph does not hold, such as "What is the river mouth of Raša (river)?", are kept, because they have no answer in the knowledge graph.

This selection was made before ASK queries were left out. Of the 68 questions the script then produced, the grammar check removed 18 and the knowledge graph check removed 5, leaving 45. Removing the 22 ASK questions among those leaves 23 SELECT questions.
